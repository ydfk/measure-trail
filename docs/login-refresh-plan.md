# 登录体验修复计划

## 范围与决定

- 登录凭证改为用户名和密码；服务启动时确保默认账号 `admin` / `111111` 存在，并允许通过环境变量覆盖首次创建时的凭证。
- 关闭所有公开注册、邮箱验证和邮箱找回密码端点；Apple 登录只允许已绑定身份，不再自动开户。
- 增加已登录用户读取及修改用户名/密码的 API，供未来 Vue 或 React Web 客户端使用。
- 历史数据正式导入默认归属配置中的默认用户名，也允许通过命令行指定其他用户名。
- 服务地址从构建配置读取，Debug 模拟器默认本机 21000，真机及 Release 默认 `https://measure-api.ydfk.site`。Debug 支持开发环境变量覆盖，Release 只接受 HTTPS，不再读取旧的手工地址。
- 延续 `docs/brand.md` 的测量弧线、蓝色系和系统字体；登录页使用正式品牌图形、全屏背景、原生输入框和清晰的主按钮，支持键盘滚动与动态字体。
- 补齐启动屏配置，解决旧式兼容显示造成的上下黑边；保留工作区现有 Xcode 项目和 Scheme 修改。
- Docker 构建阶段可编译未来 Vue/React 前端，运行镜像只包含 Go 服务与静态产物，由 Go 提供 SPA 静态文件和 API。

## 执行步骤

1. 已拉取远程并检查登录、品牌、认证服务和现有测试。
2. 修改用户表迁移、默认账号引导、用户名登录、凭证修改 API 和回归测试。
3. 修改历史数据导入默认归属和 Docker/Go 静态站点托管。
4. 修改 iOS 用户名登录界面，更新配置及接口文档。
5. 执行 Go 测试、iOS 构建、登录 UI 测试和 Docker 构建/运行检查。

## 验收

- 新安装无需手填服务地址；登录页只有用户名、密码和已绑定 Apple 身份入口，没有邮箱、注册、找回密码或服务器设置。
- 首次启动创建一个默认账号；重复启动不会覆盖用户在 Web 端修改后的用户名和密码。
- 注册、邮箱验证和邮箱找回端点不存在；已有账号仍能登录。
- 历史数据导入不传目标参数时归属默认账号。
- 单个 Docker 容器中仅运行 Go 进程，同时正确提供 API、静态资源和 SPA 回退。
- 登录页铺满屏幕、Logo 可见，键盘和大字体下仍可访问登录操作。
- 分别报告本地验证和真实服务器、Apple、真机的验证边界。

## 验证结果（2026-09-07）

- 已完成：Go 全量测试、`go vet ./...`、OpenAPI 3.0/3.1 快照和 `git diff --check`。
- 已完成：iPhone 17 Pro Max / iOS 26.5 模拟器下 27 个单元测试与 2 个 UI 测试，以及无签名 Release 模拟器构建。
- 已完成：真实旧库只读 dry-run，并向临时目标库正式导入 47 条记录；全部归属默认账号 `admin`，未改动正式数据库。
- 已完成：Docker Compose 配置校验、镜像构建和隔离容器检查；静态首页、SPA 回退、健康接口、默认账号登录与账号信息接口均成功，注册返回 404，容器内仅运行 Go 服务进程。
- 未部署、未提交或推送；真实服务器登录、Apple 登录、真机及横屏体验仍需部署后验证。
