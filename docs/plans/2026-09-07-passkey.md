# Passkey 登录与维护实施计划

## 目标

- 保留用户名和密码登录，为现有账号增加多个 Passkey。
- 登录页支持系统 Passkey 登录；“我的”支持新增、重命名和删除。
- WebAuthn RP、Origin、凭据加密密钥和 iOS App ID 均由环境配置提供。

## 实施步骤

1. 新增 Passkey 凭据迁移与加密存储，凭据 ID 只保存 SHA-256 索引；挑战保存在服务进程内，有效五分钟并且只能使用一次。
2. 基于 `go-webauthn` 提供注册选项、注册验证、可发现凭据登录、列表、重命名和删除 API，成功登录继续签发现有 access/refresh token。
3. 提供 Apple App Site Association 响应，并补充 RP ID、Origin、iOS App ID 和加密密钥的环境变量校验、Docker 示例及部署说明。
4. iOS 使用 AuthenticationServices 完成平台 Passkey 注册和登录，在登录页加入 Passkey 按钮，在“我的”加入 Passkey 管理页。
5. 更新 OpenAPI，运行 Go 测试、iOS 单元测试/构建、格式与配置检查；真实设备和正式域名关联作为部署验证项单独说明。

## 验收条件

- 未登录用户可用已登记 Passkey 获取现有 JWT 会话。
- 登录用户可维护属于自己的多个 Passkey，不能访问其他账号的凭据。
- 密码登录、Apple 登录和现有数据同步不受影响。
- 生产环境缺少或填写错误的 Passkey 配置时启动即给出明确错误。

## 验证结果

- Go 全量测试与 `go vet` 通过。
- iOS 模拟器构建、29 个 XCTest、3 个 Swift Testing 用例和 2 个 UI 测试通过。
- OpenAPI 3.0/3.1 已更新；Info.plist、entitlements、生产环境生成脚本和 Compose 示例校验通过。
- 正式域名 AASA 获取和真实设备 Passkey 注册需要部署后验证。
